# valet

Скидочные карты в телефоне: QR-коды магазинов, которые открываются на кассе даже без сети.
Валет — игральная карта, wallet — кошелёк.

PWA на Go + htmx: сервер рендерит html, база — PostgreSQL, офлайн держит service worker.

## Как устроено

- `cmd/main.go` — сборка приложения: конфиг → postgres → repository → usecase → delivery → http-сервер.
- `internal/app/delivery` — http: маршруты, вход, страницы карт, шаблоны (`templates/`) и статика (`static/`), вшитые в бинарь через `embed`.
- `internal/app/usecase` — логика: вход и сессии, карты, распознавание QR с картинки.
- `internal/app/repository` — запросы к postgres через go-jet. Каждый запрос к карте ограничен `user_id`: чужую карту не прочитать.
  Внешних ключей в схеме нет: связи между таблицами держит код.
- `internal/pkg/qr` — распознавание и рендер QR-кодов, обёртка над gozxing.
- `internal/generated` — модели и построители запросов, их генерирует `make jet` по схеме базы.
- `migrations/` — схема базы, goose.

### Офлайн

`static/sw.js` держит два кэша: статику (шрифты, стили, скрипты) и карты (список, страницы карт,
картинки кодов). Страницы — сначала из сети, из кэша — если сети нет или сессия истекла (на кассе вход
не должен прятать карту). Открытый список отдаёт service worker адреса всех карт, и он докачивает их
заранее. Такие запросы помечены заголовком `X-Valet-Prefetch` и не поднимают карту наверх списка.

При выходе service worker стирает только кэш карт, статика остаётся. Сервер отдаёт персональные
страницы и картинки с `Cache-Control: no-store`, так что в обычном кэше браузера их тоже нет.

### Сессии

Хранятся в таблице `sessions`, живут 90 дней и продлеваются при заходах (не чаще раза в сутки).

## Локально

```sh
make bin-deps          # jet, goose, golangci-lint в ./bin
make postgres-up       # postgres 17 в докере, база valet
make migrate-up
make run               # http://localhost:8000
```

Кука входа помечена `Secure`, браузеры принимают её по http только на `localhost`, поэтому открывайте
`http://localhost:8000`, а не `127.0.0.1`.

Тесты (нужен postgres с накатанными миграциями):

```sh
make test
make lint
```

## Пользователи

Регистрация открытая: кнопка «Зарегистрироваться» на странице входа, `/register`. Логин — от 3 до 32 букв,
цифр, точек, дефисов и подчёркиваний, хранится в нижнем регистре, вход без учёта регистра. Пароль — от 8 символов
и не длиннее 72 байт (предел bcrypt). Сразу после регистрации пользователь вошёл.

id пользователя — UUID версии 7, его генерирует приложение при регистрации.

## Прод

VPS с docker, postgres и Caddy. Caddy выпускает TLS-сертификат и проксирует на `127.0.0.1:8000`,
пример — `Caddyfile.example`. PWA без https не работает: service worker и камера требуют защищённого соединения.

Пуш в `main` запускает `.github/workflows/pipeline.yml`: тесты и линтер → образ в Docker Hub →
миграции через ssh-туннель → перезапуск контейнера на сервере.

Что задать в настройках репозитория на GitHub:

| Где | Имя | Что |
|---|---|---|
| variables | `DOCKERHUB_USERNAME` | логин Docker Hub, образ будет `<логин>/valet` |
| variables | `SSH_HOST`, `SSH_USER` | куда деплоить |
| variables | `DOMAIN` | домен приложения, на него ставится кука входа |
| secrets | `DOCKERHUB_TOKEN` | токен Docker Hub с правом push |
| secrets | `SSH_PRIVATE_KEY`, `SSH_KNOWN_HOSTS` | ключ и отпечаток сервера |
| secrets | `PG_DSN` | строка подключения к postgres на сервере |

Бэкапов нет: если сервер умрёт, карты придётся заводить заново.
